# 에디터 블록·요소 편집 규칙 (백엔드 전달용)

에디터의 **섹션 구조 탭(#32)** 과 **요소 편집 탭(#33)** 을 만들면서 프런트에서 정한 사이트 규칙을 정리한 문서입니다.
저장·검증 API를 만들 때 같은 기준을 쓸 수 있도록 블록별 데이터 형태, 글자 수와 개수 제한, 필수 항목, 이미지 규칙, 배치 규칙을 담았습니다.

- 프런트는 입력 편의를 위해 아래 제한을 입력창에서 막고 있습니다. **서버에서도 같은 기준으로 다시 검증**해 주세요.
- 값 가운데 "제안값"으로 표시한 것은 팀 안에서 정한 임시 값이라 서버와 협의 후 바뀔 수 있습니다.
- 사이트 테마(`theme`, #34)는 아직 정해지지 않아 이 문서에 포함하지 않았습니다.
- 맨 아래 **"백엔드에 확인·결정을 요청하는 항목"** 을 먼저 보셔도 좋습니다.

코드 기준 위치: 블록 타입 `src/entities/block/types.ts`, 제한 값 `src/entities/block/model/limits.ts`, 반폭 가능 여부 `src/entities/block/model/variants.ts`, 필수 필드 `src/entities/block/model/required.ts`, 기본 문구 `src/entities/block/model/placeholders.ts`, 줄 구성 규칙 `src/features/editor-site/model/structure.ts`.

## 1. 사이트 데이터 구조

```ts
SiteContent {
  theme: ThemeConfig;        // #34에서 정함 (이 문서 범위 밖)
  rows: Row[];               // 위에서 아래 순서
}

Row {
  id: string;
  sections: [Section] | [Section, Section];   // 1개(전체 폭) 또는 2개(왼쪽, 오른쪽 50:50)
}

Section {                    // type에 따라 variant와 content의 모양이 정해집니다
  id: string;
  type: 'header' | 'hero' | 'text' | 'list' | 'gallery' | 'footer';
  variant: string;           // 블록 종류별 구조. 아래 3장 참고
  content: ...;              // 블록 종류별 내용. 아래 3장 참고
}

BlockImage { url: string; scale?: number }   // 사진 한 장. 아래 4장 참고
```

저장 예시(일부):

```json
{
  "rows": [
    { "id": "row-a1", "sections": [
      { "id": "section-h1", "type": "header", "variant": "horizontal",
        "content": { "brandName": "카페 오롯", "logo": { "url": "https://…/logo.png", "scale": 1 } } }
    ]},
    { "id": "row-a2", "sections": [
      { "id": "section-t1", "type": "text", "variant": "single",
        "content": { "title": "우리 이야기", "body": "…", "align": "center" } },
      { "id": "section-g1", "type": "gallery", "variant": "grid",
        "content": { "images": [{ "url": "https://…/1.jpg" }, { "url": "https://…/2.jpg" }] } }
    ]}
  ]
}
```

- `rows` 배열의 순서가 화면의 위→아래 순서이고, 한 줄 안에서는 `sections` 배열의 순서가 왼쪽→오른쪽입니다.
- `id`는 지금 프런트가 새 줄·블록·목록 항목을 만들 때 `row-xxxxxxxx`, `section-xxxxxxxx`, `item-xxxxxxxx`(8자리 임의 값)로 만듭니다. 서버가 발급할지, 프런트가 만든 값을 그대로 둘지는 하단 7번 항목에서 정해 주세요.

## 2. 줄 구성과 배치 규칙

| 규칙 | 내용 |
|---|---|
| 한 줄의 블록 수 | 1개(전체 폭) 또는 2개(50:50). 3개 이상은 없습니다. |
| 헤더 | **맨 위 줄에만** 올 수 있고 사이트에 **최대 1개**입니다. 삭제는 가능합니다. |
| 푸터 | **맨 아래 줄에만** 올 수 있고 사이트에 **최대 1개**입니다. 삭제는 가능합니다. |
| 히어로 | 개수 제한 없음 (협의 전, 하단 4번 항목). |
| 그 밖의 블록 | 헤더 앞이나 푸터 뒤로는 올 수 없고, 개수 제한이 없습니다. |
| 나란히 배치 가능 여부 | 아래 표의 "반폭 가능" 구조끼리만 한 줄에 둘을 놓을 수 있습니다. |
| 전체 폭 전용 구조 | 반드시 **혼자 한 줄**이어야 합니다. |
| 빈 사이트 | 블록이 하나도 없는 사이트(`rows: []`)를 허용합니다. (빈 템플릿) |

### 구조(variant) 목록과 반폭 가능 여부

| 블록 | variant (저장 값) | 이름 | 반폭 가능 |
|---|---|---|---|
| header | `horizontal` | 가로형 | 아니오 (전체 폭 전용) |
| header | `centered` | 중앙형 | 아니오 |
| hero | `fullImage` | 전면 이미지형 | 아니오 |
| hero | `split` | 좌우 분할형 | 아니오 |
| hero | `textOnly` | 텍스트형 | 아니오 |
| text | `single` | 단일 컬럼형 | **예** |
| text | `withImage` | 이미지 병행형 | 아니오 |
| list | `card` | 카드 그리드형 | **예** |
| list | `row` | 리스트 행형 | **예** |
| list | `compact` | 컴팩트 타일형 | **예** |
| list | `zigzag` | 좌우 교차형 | 아니오 |
| gallery | `grid` | 균일 그리드형 | **예** |
| gallery | `featured` | 대표+썸네일형 | **예** |
| gallery | `single` | 단일 액자형 | **예** |
| footer | `simple` | 심플형 | 아니오 |
| footer | `info` | 정보형 | 아니오 |

### 서버 검증 제안
- 줄 하나에 블록이 3개 이상이면 거부합니다.
- 블록이 2개인 줄에 "전체 폭 전용" 구조가 있으면 거부합니다. (프런트는 이런 상태를 만들지 않습니다.)
- 헤더가 맨 위 줄이 아니거나 푸터가 맨 아래 줄이 아니면, 또는 각각 2개 이상이면 거부합니다.
- 존재하지 않는 `type`/`variant` 조합은 거부합니다.

## 3. 블록별 필드 규칙

공통 표기: **필수**는 배포할 때 비어 있으면 안 되는 항목입니다(편집·저장 중에는 비워도 됨, 6장 참고). "선택"을 비우면 프런트는 필드 자체를 **제거**합니다(빈 문자열로 저장하지 않음). 글자 수는 입력한 글자 기준이고, 앞뒤 공백은 지운 뒤 비었는지 판단합니다.

### 3-1. 헤더 (`header`)

| 필드 | 필수 | 형식 | 제한 | 비고 |
|---|---|---|---|---|
| `brandName` | **필수** | 문자열 | 최대 20자 | 상호명 |
| `logo` | 선택 | BlockImage | 1장 | 크기(`scale`) 조절 가능 |

- **표시 규칙(변경됨)**: 로고가 있으면 **[로고 이미지] 상호명**을 나란히 보여 줍니다. 이전에는 로고가 있으면 상호명이 사라졌습니다.
- 로고가 없거나 이미지를 불러오지 못하면 상호명만 보입니다.
- 구조(가로형/중앙형)는 정렬만 다르고 내용은 같습니다.

### 3-2. 히어로 (`hero`)

| 필드 | 필수 | 형식 | 제한 | 비고 |
|---|---|---|---|---|
| `title` | **필수** | 문자열 | 최대 30자 | |
| `subtitle` | 선택 | 문자열(줄바꿈 가능) | 최대 100자 | |
| `badges` | 선택 | 문자열 배열 | **최대 3개**, 각 최대 12자 | 첫 화면의 뱃지(강조 특징). 대소문자 무시하고 같은 글은 넣을 수 없음 |
| `image` | 선택 | BlockImage | 1장 | `fullImage`, `split`에서만 표시. 크기 조절 가능 |

- **삭제된 항목**: 초기 기획의 "버튼 문구"는 없습니다. 히어로에는 버튼이 없습니다.
- `textOnly`에서는 `image`를 쓰지 않지만 값은 지우지 않고 보존합니다.

### 3-3. 줄글 (`text`)

| 필드 | 필수 | 형식 | 제한 | 비고 |
|---|---|---|---|---|
| `title` | 선택 | 문자열 | 최대 30자 | |
| `body` | **필수** | 문자열(줄바꿈 가능) | 최대 1000자 | |
| `image` | 선택 | BlockImage | 1장 | `withImage`에서만 표시. 크기 조절 가능 |
| `align` | 선택 | `'left' \| 'center' \| 'right'` | | **신규 필드.** 기본 `left`. **줄글에서만** 있음 |

- `single`에서는 `image`를 쓰지 않지만 값은 보존합니다.
- 글 정렬은 줄글에서만 고를 수 있습니다. 다른 블록의 정렬은 구조(variant)로 정해집니다.
- **삭제된 항목**: 초기 기획의 "강조 문구형" 구조는 없습니다. 줄글 구조는 `single`, `withImage` 두 가지입니다.

### 3-4. 목록 (`list`)

| 필드 | 필수 | 형식 | 제한 | 비고 |
|---|---|---|---|---|
| `title` | 선택 | 문자열 | 최대 20자 | 섹션 제목 |
| `items` | - | ListItem 배열 | **최대 30개**, 비어 있어도 됨 | 배열 순서가 화면 순서 |

`ListItem`:

| 필드 | 필수 | 형식 | 제한 | 비고 |
|---|---|---|---|---|
| `id` | 필수 | 문자열 | | 항목 식별자. 순서 변경에 쓰임 |
| `name` | **필수** | 문자열 | 최대 20자 | 항목 이름 |
| `description` | 선택 | 문자열 | 최대 40자 | |
| `price` | 선택 | 자유 문자열 | 최대 12자 | "4,000원", "시가" 등. 숫자로 강제하지 않음 |
| `image` | 선택 | BlockImage | 1장 | `card`, `row`, `zigzag`에서 표시. `compact`에서는 값만 보존. 크기 조절 없음 |

- **삭제된 항목**: 초기 기획의 항목 "그룹"은 없습니다.

### 3-5. 갤러리 (`gallery`)

| 필드 | 필수 | 형식 | 제한 | 비고 |
|---|---|---|---|---|
| `images` | - | BlockImage 배열 | **최대 12장**, 비어 있어도 됨 | 배열 순서가 화면 순서. **첫 번째 사진이 대표** |

- 첫 번째 사진은 `featured`에서 크게, `single`에서 액자에 표시됩니다. `single`은 **첫 번째 사진 한 장만** 보여 주고 에디터도 한 장만 올리게 하며, 나머지 사진은 값만 보존합니다.
- `grid`는 모든 사진을 같은 크기로 보여 줍니다.
- 첫 번째 사진의 `scale`만 화면에 쓰입니다(`featured`, `single`). 나머지 사진은 크기 조절이 없습니다.
- 에디터에서 사진 칸을 비워 두는 경우 `{ "url": "" }`로 저장될 수 있습니다. 4장을 참고해 주세요.
- **삭제된 항목**: 갤러리 섹션 제목, 사진별 설명 글은 없습니다.

### 3-6. 푸터 (`footer`)

| 필드 | 필수 | 형식 | 제한 | 비고 |
|---|---|---|---|---|
| `brandName` | **필수** | 문자열 | 최대 20자 | 상호명 |
| `address` | 선택 | 문자열 | 최대 60자 | |
| `phone` | 선택 | 문자열 | 최대 20자 | 숫자, `+`, `-`, `(`, `)`, 공백만 입력 가능 |
| `hours` | 선택 | 문자열 | 최대 40자 | 자유 텍스트 |
| `social` | 선택 | `{ kind, url }` 배열 | **최대 5개**, `url` 최대 200자 | 7장 참고 |
| `copyright` | 선택 | 문자열 | 최대 40자 | 비우면 화면에서 `© 올해 상호명`으로 자동 표시 |
| `email` | 선택 | 문자열 | 최대 50자 | **info 전용.** 이메일 형식이 아니면 에디터가 오류 안내 |
| `businessInfo.representative` | 선택 | 문자열 | 최대 20자 | **info 전용.** 대표자명 |
| `businessInfo.registrationNumber` | 선택 | 문자열 | 숫자 10자리 | **info 전용.** `000-00-00000` 형태(하이픈 포함)로 저장 |

- `simple` 구조에서는 `email`, `businessInfo`를 쓰지 않지만 값은 보존합니다(에디터가 "이 구조에서는 표시되지 않아요"로 안내).
- `businessInfo`의 두 값이 모두 비면 `businessInfo` 자체를 제거합니다.

## 4. 이미지 규칙

`BlockImage { url: string; scale?: number }`

| 항목 | 규칙 |
|---|---|
| 허용 형식 | `image/png`, `image/jpeg` (png, jpg, jpeg) |
| 파일 크기 제한 | **미정.** 백엔드와 정해서 채울 예정 (하단 1번 항목) |
| 한 칸당 장수 | 헤더 로고, 히어로, 줄글, 목록 항목은 1장. 갤러리는 최대 12장 |
| `scale` | **1 ~ 2**, 0.05 단위. 1이 사진 전체가 보이는 기본 상태이고 2는 2배 확대(가운데 부분이 확대되고 넘치는 부분은 잘림). 없으면 1 |
| `scale`이 쓰이는 곳 | 헤더 로고(로고 크기, 기본 높이의 배수), 히어로 `fullImage`/`split`, 줄글 `withImage`, 갤러리 첫 번째 사진(`featured`, `single`). 목록 항목과 갤러리의 나머지 사진은 쓰지 않음 |
| 없는 사진 | 필드가 없거나(`undefined`) `url`이 빈 문자열(`""`)입니다. 화면에는 이미지 대체 화면(색 블록과 아이콘)이 나오거나, 블록에 따라 이미지 영역이 사라집니다. 헤더 로고는 대체 화면 없이 상호명만 보입니다. |

### 중요: 임시 주소
지금 에디터는 올린 사진을 서버에 보내지 않고 **브라우저 임시 주소(`blob:http://…`)** 로 화면에만 보여 줍니다. 사진 업로드 API가 생기면 올린 뒤 받은 주소로 교체합니다.
- 서버는 **`blob:` 같은 임시 주소가 저장되지 않도록** `url`이 `http`/`https`(또는 내부 규칙의 업로드 주소)인지 검증해야 합니다.
- 어떤 호스트의 주소를 허용할지(자체 업로드 저장소만 허용할지)도 정해 주세요.

## 5. 구조(variant) 변경과 내용 보존 규칙

- 구조를 바꿔도 **입력한 내용은 지우지 않습니다.** 블록의 `content`는 구조와 상관없이 같은 값을 공유합니다. 다른 구조에서 쓰이지 않는 값(예: 줄글 `single`의 `image`, 히어로 `textOnly`의 `image`, 목록 `compact`의 항목 `image`, 푸터 `simple`의 `email`·`businessInfo`, 갤러리 `single`의 두 번째 이후 사진)은 보존하고, 에디터는 흐리게 보여 줍니다.
- 구조를 **전체 폭 전용으로 바꾸면** 그 블록이 나란히 놓여 있던 줄은 풀립니다. 왼쪽 블록은 원래 줄에 남고 오른쪽 블록은 바로 아래 새 줄이 되어, 화면에 보이는 순서는 그대로입니다. (서버가 구조 변경을 직접 처리한다면 같은 규칙을 적용해 주세요.)
- 나란히 놓인 두 블록 중 하나를 지우면 남은 블록은 전체 폭 줄(혼자 한 줄)이 됩니다.

## 6. 필수 입력과 배포 점검

### 편집 중
- 필수 필드가 비어 있어도 **저장은 허용**합니다(자동 저장·수동 저장 모두).
- 에디터는 필수 필드에 `*` 표시를 하고, 비어 있으면 "입력해 주세요" 안내만 보여 줍니다.

### 배포할 때 (서버도 같은 기준으로 검사해 주세요)
필수 필드 5개:

| 블록 | 필드 |
|---|---|
| header | `brandName` |
| hero | `title` |
| text | `body` |
| list | 각 항목의 `name` |
| footer | `brandName` |

- 필수 필드가 **비어 있거나 기본 문구 그대로**이면 배포를 막습니다.
- 선택 필드가 기본 문구 그대로이면 **경고**합니다. 프런트는 "수정하러 가기"와 "그래도 배포하기"를 고를 수 있게 할 예정입니다.
- 배포 점검 응답은 어느 블록의 어느 필드가 문제인지(블록 `id`, 필드 이름, 사유: 비어 있음/기본 문구) 알려 주는 형태가 필요합니다. (프런트가 해당 블록으로 이동하는 데 씁니다.)

### 기본 문구 목록
새 블록을 추가하면 아래 문구가 들어갑니다. 값이 **아래 문구와 정확히 같을 때**(앞뒤 공백 제외) "기본 문구 그대로"로 봅니다.

| 위치 | 기본 문구 |
|---|---|
| 헤더, 푸터 상호명 | `사이트 이름` |
| 히어로 제목 | `제목을 입력해 주세요` |
| 히어로 부제 | `소개 문구를 입력해 주세요` |
| 줄글 제목 | `제목` |
| 줄글 본문 | `내용을 입력해 주세요` |
| 목록 섹션 제목 | `섹션 제목` |
| 목록 항목 이름 / 설명 / 가격 | `메뉴 이름` / `설명` / `가격` |
| 푸터 주소 | `가게 주소를 입력해 주세요` |
| 푸터 전화번호 | `전화번호를 입력해 주세요` |
| 푸터 영업시간 | `영업시간을 입력해 주세요` |

템플릿으로 시작한 사이트의 샘플 문구도 같은 방식으로 봅니다: `우리 가게 이름`, `우리 가게를 소개하는 한 줄`, `가게의 특징과 분위기를 짧게 적어 주세요`, `대표 특징 1`, `대표 특징 2`, `우리 가게 이야기`, `가게를 시작한 이유와 소개하고 싶은 이야기를 적어 주세요.`, `주소를 입력해 주세요`, `연락처를 입력해 주세요`, `영업시간을 입력해 주세요`, `메뉴 이름 N`(N은 숫자), `메뉴 설명을 적어 주세요`, `0,000원`.

AI 초안에서 푸터 항목을 켜고 비워 둔 경우의 대체 문구도 위 푸터 문구(`가게 주소를 입력해 주세요` 등)와 같습니다.

## 7. SNS 링크 규칙

푸터 `social`은 `{ kind, url }` 배열입니다. 에디터는 **주소만 입력**받고 `kind`는 주소의 도메인으로 정해서 같이 저장합니다.

| 도메인 | `kind` 저장 값 | 푸터 표시 이름 |
|---|---|---|
| `instagram.com` | `instagram` | Instagram |
| `facebook.com`, `fb.com` | `facebook` | Facebook |
| `youtube.com`, `youtu.be` | `youtube` | YouTube |
| `blog.naver.com`, `tistory.com` | `blog` | 블로그 |
| `kakao.com`(`pf.kakao.com`, `open.kakao.com` 등) | `kakao` | 카카오톡 |
| `x.com`, `twitter.com` | `X(트위터)` | X(트위터) |
| 위에 없는 도메인 | `""`(빈 문자열) | 주소의 도메인 이름(예: `linktr.ee`) |

- `url`은 **`http://` 또는 `https://`로 시작하는 주소만** 허용합니다. 다른 형식은 푸터에서 링크로 쓰지 않습니다(에디터는 입력 중 오류 안내).
- 푸터에서는 이름을 누르면 `url`로 이동합니다(새 탭, `rel="noopener noreferrer"`).
- `kind`가 위 표의 영문 키가 아닌 값(예: `X(트위터)`)이면 **저장된 글자 그대로** 푸터에 표시됩니다.
- `kind` 값 목록은 임시입니다. 특히 X의 값이 영문 키가 아니라 `X(트위터)`로 되어 있는 점을 정리해 주세요(하단 6번 항목).

## 백엔드에 확인·결정을 요청하는 항목

1. **파일 크기 제한**: 사진 파일 한 장의 최대 크기. (프런트는 아직 형식만 검사합니다.)
2. **사진 업로드 방식과 주소**: 업로드 API 형태(multipart, 미리 서명된 주소 등), 업로드 후 저장되는 `url`의 형식과 허용 호스트. 임시 `blob:` 주소가 저장되지 않게 검증해 주세요.
3. **글자 수 세는 기준**: 프런트의 입력 제한은 브라우저의 `maxLength`(UTF-16 단위)입니다. 이모지처럼 두 칸을 차지하는 문자가 서버의 글자 수 기준과 어긋나지 않도록 세는 방식을 맞춰 주세요.
4. **개수 제한 값**: 목록 항목 30개, 갤러리 사진 12장, 푸터 SNS 링크 5개, 히어로 뱃지 3개는 제안값입니다. 히어로 블록 개수는 제한이 없습니다(필요하면 상한을 정해 주세요).
5. **데이터 필드 추가·변경**: 줄글에 `align`(`left`/`center`/`right`, 선택)을 추가해 주세요. 헤더는 로고가 있어도 상호명을 함께 표시하도록 규칙이 바뀌었습니다(필드 변경은 없음).
6. **SNS `kind` 값 목록**: 위 표의 영문 키(`instagram`, `facebook`, `youtube`, `blog`, `kakao`)를 확정하고, X의 값을 `x`로 할지 `X(트위터)`로 둘지 정해 주세요. 목록에 없는 도메인은 빈 문자열로 둡니다.
7. **id 발급**: 줄, 블록, 목록 항목 `id`를 서버가 발급할지, 프런트가 만든 임시 값(`row-xxxxxxxx` 등)을 그대로 저장할지 정해 주세요.
8. **배포 점검 API**: 필수 필드와 기본 문구 검사 결과를 6장의 형태(블록 `id`, 필드, 사유)로 돌려줄 수 있는지, 배포 요청 시 서버가 같은 검사를 하는지 확인해 주세요.
9. **저장 시 정합성 검증**: 2장의 "서버 검증 제안"(줄 안 블록 수, 전체 폭 전용 구조 혼자 한 줄, 헤더·푸터 위치와 개수)을 저장 요청에서 검증할지 정해 주세요.
10. **사이트 이름**: 지금 에디터의 사이트 이름은 헤더의 상호명을 그대로 씁니다. 별도 사이트 이름 필드를 둘지 정해 주세요.
